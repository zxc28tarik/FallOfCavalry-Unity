Adaptation
- Whole clothed humanoid: 9,586 source triangles, one skin, 23 source bones.
- Preserve the original source geometry, hierarchy, bind transforms and weight
  data byte-for-byte; no authored reweighting. Unity's importer limitations are
  recorded below rather than claiming bit-identical runtime weights.
- Add semantic FOC sockets as child markers, not replacement deformation bones.
- Explicit Unity Humanoid mapping: source Chest -> Human Spine, source
  UpperChest -> Human Chest; retain all source transforms.
- The supplied FBX's saved object pose is Running, not its original bind pose.
  Derive the reference/prefab pose from existing skin bind matrices. Do not
  create a new rig or bake that Running pose into the Avatar reference.
  The pilot prefab stores the actual bind pose with Animator initially disabled;
  the review explicitly enables animation only when a real clip is requested.
- Imported weights are checked finite, normalized, and at most four influences.
  This is not a claim of bit-identical Unity floating-point weight values.
  A source audit found 946 tiny influences below 0.001 across 889/13520 source
  vertices. Unity clamps its minimum importer threshold to 0.001, so pruning
  and normalization are possible. Simulated maximum removed mass per affected
  vertex is 0.00167625 (0.167625%). Original source weights are not rewritten.
- Base color reduced from 8192 to 2048 for the pilot. Metallic and roughness
  reduced from 4096 to 2048 and packed for Unity Standard: RGB metallic,
  alpha = 1 - roughness. No invented normal map or flat replacement colors.
  Additional 4096/1024 material comparison variants use the same explicit opaque,
  non-emissive Standard shader, compression and mipmaps.
- Walking and Running are the only source clips. They must be tested as real
  Unity Humanoid animation, not renamed proof animation.
- For the in-place FOC view, source vertical root movement is baked into pose
  while gameplay remains responsible for world travel. Discarding the Y root
  curve together with XZ causes artificial hovering; the real Windows capture
  measures mesh minimum Y against the same original-source phase for this reason.
- Ground contact is NOT production accepted. An independent Blender 4.5.9 audit
  of the original FBX at 12 Walking phases i/12 found minimum mesh heights from
  -0.036917649 to +0.009071807 m (rest minimum approximately zero). The lowest
  vertex at phase 1/3 belongs to LeftToes/LeftFoot. Source toe penetration is
  therefore inherited, not fully explained by Unity import. The capture suite
  compares each Walking sample to its source value with a 0.005 m import-drift
  tolerance; passing this comparison does not approve foot contact. No floor
  lowering, per-phase grounding offset or source animation rewrite is applied.

Integration boundary
The Meshy skeleton is NOT the FOC canonical 18-bone modular skeleton.
CanonicalRig/RigValidator remain unchanged and reject this foreign descriptor.
A valid Unity Human Avatar does not overturn that result.

The pilot uses its own transient Standard-only VisualCatalog and the existing
VisualSoldier3DAssembler/cache/pool. Body/head/clothing semantic slots alias one
indivisible consolidated character. Only ONE character mesh is instantiated;
Narrative and Crowd are explicitly unsupported to prevent duplicate geometry.
This is not yet interchangeable body/head/clothing production modularity.
Gameplay SoldierInstance, persistent loadout, deterministic signatures, domain,
save schema v14, and production historical catalog are unchanged.

Source limitations / pending production work
- One supplied LOD0; genuinely reduced LOD1/LOD2 have 5752/2396 triangles.
  Decimated weights are limited/renormalized to four influences; source LOD0 is
  unchanged. Derived surface/weight errors are recorded in optimization-manifest.
  Three skins share one retained rig, with one renderer selected per LOD.
- No finger bones. Hand sockets do not establish a correct weapon grip.
- No Idle, Attack, Crouch, mounted locomotion or seated animation was supplied.
- Walking toe penetration needs motion/foot-contact cleanup before production.
- The existing proof shared library is not a production Humanoid muscle library.
  Existing articulated HasanMotionReview generic diagnostic clips are converted
  using their unchanged Avatar to real Humanoid muscle/body curves for this pilot.
  Conversion does not improve choreography or certify clothing/contact quality.
- Mounted integration is deliberately rejected until pelvis/saddle alignment
  and actual mounted deformation are demonstrated.
- Sipahi, Cebeli and Tufekci replacements are not supplied by this pilot.
- Historical and final visual review are separate from technical import tests.
- Optional actual-path 1/12/100 runtime benchmark follows on-foot review. It is
  opt-in with Test-MeshyPilot -RunBenchmark; null performance means NOT RUN.
  250/500 and proof-versus-production comparison remain outside this pilot.

Reproduction
Prepare source: Tools/Art/Prepare-MeshyPilot.ps1
Generate import/prefab: Unity -batchmode -nographics -projectPath UnityProject
  -executeMethod FOC.Editor.Visuals.MeshyHasanPilotPipeline.Run -logFile <log>
Convert existing FOC diagnostic motions: Unity -batchmode -nographics
  -projectPath UnityProject -executeMethod
  FOC.Editor.Visuals.MeshyHasanPilotMotionAdaptation.Run -logFile <log>
Final clean-SHA local evidence: Tools/Test-MeshyPilot.ps1 -UnityEditor <path>
That runner restores/builds/tests .NET, verifies imported pilot assets, runs all
Unity EditMode tests, builds the Windows pilot, captures real rendered images,
and records exact commands, exit codes, initial/final SHA and worktree state.
Evidence is run-specific under TestResults/MeshyPilot/Runs/<sha>/<run-id>.
AllowDirtyDiagnostic is exploratory evidence, never final-SHA acceptance.
