action (0, 1/8, ..., 7/8), for all six actions:
  original generic donor -> HumanPose Get/Set on the SAME donor Avatar;
  direct HumanPose -> generated-clip playback on that same Avatar;
  direct HumanPose -> generated-clip playback on the Meshy Avatar.
Foot IK, playable IK, root-motion application and automatic controllers are off.

Blocker / decision
There is no demonstrated visually acceptable existing-FOC-to-Meshy action
retarget for the required gate. A valid Human Avatar and mathematically valid
muscle clips do not establish compatible reference semantics, deformation or
contact. Do not blame the visible difference solely on source choreography:
the same source can reconstruct closely on its own Avatar but differs markedly
on Meshy. A separately validated reference/retarget adapter would be needed.
No blind muscle clamp, foot offset, shared-rig rewrite or production activation
was performed. Required retarget visual acceptance remains FAIL / NOT READY.

Source-immutable helper lifecycle review
The roundtrip helper writes only its external evidence JSON. It does not call
SaveAssets, save a prefab, modify a shared mesh, or overwrite either source
Avatar. Transform/Animator changes and SampleAnimation operate on clones.
HumanPoseHandlers are disposed by using; finally destroys graphs before clone
objects and then the temporary Generic Avatar, including exception paths.
All five clone initializations are inside that cleanup scope. Clone also
destroys its own temporary object if initialization fails before returning it.
The source Human Avatars are never destroyed. This narrow cleanup repair does
not alter the sampled motion, reference rig, comparison or quality criteria.
