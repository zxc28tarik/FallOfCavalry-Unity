# UX information hierarchy

The shell is a dense desktop workspace with three structural regions: primary navigation, scrollable decision workspace and contextual detail/preview. At compact desktop width the context panel collapses; information remains reachable through the workspace.

Each major screen starts with six decision questions:

1. Current — authoritative visible state.
2. Trend — only with comparable history; otherwise `InsufficientHistory`.
3. Why — only explicit gameplay factors; otherwise an unavailable reason.
4. Risk — known rule plus visible state, never prediction from hidden truth.
5. Opportunity — a currently legal/known possibility.
6. Action — a typed intent routed to an Application service.

Details use foldouts and virtualized drill-down lists. City retains exactly nine current areas. Character keeps loyalty, satisfaction, relation, reputation and standing separate. Organization keeps membership, assignment, location and authority separate and displays all eight branches. Army keeps morale, fatigue and discipline separate. Diplomacy keeps relation, factor and action separate. Battle displays sectors, deployment, orders and result without becoming the simulator.

Empty, unknown, unavailable, stale and no-selection states are first-class. Critical meaning is expressed by label and severity as well as color. Raw enum values are mapped to localization keys.
